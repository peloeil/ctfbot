# VC 読み上げ

VC 付属のテキストチャットに投稿されたメッセージを、VOICEVOX で読み上げる。読み上げは参加者ごとの opt-in で、`/read join` した人だけが対象になる。`TTS_VOICEVOX_URL` が未設定なら機能全体が無効で、cog を追加せず、コマンドも `/help` にも出ない。

実装: [tts/](../../src/ctfbot/features/tts/)。検証: [test_tts.py](../../tests/test_tts.py)・[test_tts_service.py](../../tests/test_tts_service.py)。実音声の確認は自動テストに含めず、人間が VC で行う。

## コマンド

すべて guild 限定で、応答は ephemeral。Discord の組み込み `/tts`（テキストチャットの読み上げ）と紛らわしいため、グループ名は `/read` にしている。`/read stop` は bot 全体ではなくこの機能の読み上げ停止を指す。

| コマンド | 動作 |
|---|---|
| `/read join` | 実行者を読み上げ対象に加える。bot が未接続なら実行者の VC へ接続する。同じ VC に接続済みなら再接続しない。別の VC で稼働中なら「既に別の VC で読み上げ中です。」と断る |
| `/read leave` | 実行者を対象から外す。対象が 0 人になったら切断する。`manage_guild` を持つ実行者は全員を外して切断する |
| `/read skip` | 再生中の読み上げを止めて次へ進む。対象者または `manage_guild` のみ |
| `/read stop` | 待機中のキューと合成中の項目を破棄し、再生も止める。接続は維持する。対象者または `manage_guild` のみ |
| `/read members` | 読み上げに参加している人と、それぞれのセッションの声を参加した順に表示する。誰でも実行でき、VC への在室・opt-in は不要。defer しない |
| `/read voice show` | 保存済みの声（なければ自動で割り当てられる声）と、読み上げ中なら現在の声を表示する。クレジット付き |
| `/read voice set voice:<声>` | 声を選んで保存する。`voice` は autocomplete 付きの文字列で、style ID の数字列かラベル（「キャラクター名（スタイル名）」）の完全一致を受け付ける。候補は `TTS_SPEAKER_IDS` の声だけに絞る |
| `/read voice reset` | 保存済みの声を削除して自動に戻す。設定がなければ「声は既に自動です。」 |

`/read voice` の 3 コマンドは guild のメンバーなら誰でも使える。VC への在室・opt-in・読み上げ中であることは不要で、操作できるのは自分の設定だけ（`manage_guild` でも他人の声は変えられない）。VOICEVOX や DB への問い合わせを伴うので、先に defer する。

### `/read members`

名前を読まず声で投稿者を区別する方式なので、「どの声が誰か」を確かめる手段として置く。「参加者」は opt-in 中の人（`session.voices` のキー）で、VC にいても `/read join` していない人は載せない。同じ VC にいれば分かる程度の情報なので、権限は課さない。DB も HTTP も使わないので defer せず、カタログもメモリのものだけを使う。

- 表示は VC のメンション、参加者の総数、参加者ごとの `- 表示名: 声のラベル`。実行者の行にだけ「（あなた）」を付ける。表示名は `escape_markdown` で整える。ユーザーのメンションは、クライアントのキャッシュ次第で「@不明なユーザー」になるので使わない。表示名は声との対応を確かめるためだけに出し、読み上げには使わない。
- 並びは `session.voices` の挿入順（参加順）。先に参加した人が声を優先するので、声が重複した理由を読み取れる。`set`・`reset` で声を差し替えても順序は変わらず、抜けて再 join すると末尾に移る。
- `get_member` が `None` なら「不明なメンバー」と書く。await を挟まないため fetch はしない。カタログがなければ声は「ID n」。
- セッションがなければ「読み上げは開始されていません。」、参加者 0 人（退出猶予中）なら参加者がいない旨を返す。
- 最大 20 人かつメッセージ全体 1900 文字以内（`MAX_MESSAGE_CONTENT_LENGTH`）まで表示し、残りは「他 N 人」とする。声のラベルは ENGINE 由来で長さに上限がなく、人数だけでは文字数を抑えられないため。分割やページングは、ephemeral の一覧には状態管理が過剰なので採らない。
- クレジットと、保存済みか自動かは載せない。クレジットは声を使う本人への応答（`join`・`voice show`・`voice set`）に表示済みで、全員分を並べると文字数を圧迫する。保存済みかの判定は参加者ごとの DB 読み取りが要り、await が入って一覧が一瞬の状態でなくなる。

`/read join` は実行者が `VoiceChannel` にいることを要求する（stage channel は不可）。bot に VC の View Channel・Connect・Speak がない場合と、ffmpeg・libopus が使えない場合（「音声再生の準備ができていません。」）も断る。接続は数秒かかり得るため defer してから実行し、結果を followup で返す。接続は `self_deaf=True`。成功時の応答には、セッションの声とクレジットを含める。接続の失敗（タイムアウト、`ClientException`、`OpusNotLoaded`、davey 不足の `RuntimeError`）では、残った `guild.voice_client` を `disconnect(force=True)` で片付ける。

## 読み上げる投稿

次をすべて満たす投稿だけを読む。`on_message` のみが対象で、編集は読まない。

- `GUILD_ID` の guild で、bot・Webhook・システムメッセージ（default と reply 以外）ではない。
- bot が接続している VC のテキストチャットへの投稿である。
- 投稿者が `/read join` 済みで、かつその VC に在室している。
- 正規化後の本文が空でない。添付・スタンプのみ、URL のみ、スポイラーのみの投稿は読まない。
- 本文に bot へのメンションを含まない（bot 宛ての投稿を読み上げないため）。返信先への ping だけの投稿は読む。

opt-in した人が VC から離れると opt-in は解除され、再入室しても読み上げは再開しない。`/read join` をやり直す。opt-in・キューはメモリのみで、切断・再起動で消える。

## テキスト正規化

本文を Discord 非依存の `normalize_text`（[service.py](../../src/ctfbot/features/tts/service.py)）で整える。**表示名は読まない**（VOICEVOX にも送らない）。声で投稿者を区別できるので名前は冗長で、読み上げ時間が延びるだけになるため、読み上げに戻す設定も設けない。コードブロック、インラインコード、URL、Markdown リンクの URL 部分（ラベルは残す）、カスタム絵文字、ユーザー・ロール・チャンネル・コマンドのメンション、`@everyone`・`@here`、タイムスタンプ、Markdown の装飾記号、引用・見出し・リスト記号、ゼロ幅文字を除く。スポイラーは記号だけでなく**中身ごと**除く。

同じ文字が 4 回以上続く場合は 3 回に縮め、改行は「、」、連続する空白は 1 つにする。本文は `TTS_MAX_CHARS`（既定 100）で切り詰め、切り詰めた旨は読まない。上限は ENGINE のメモリ使用量も決める（[メモリ](#メモリ)）。

## 声の割り当て

用語: **声**は VOICEVOX の style ID（表示は「キャラクター名（スタイル名）」）、**カタログ**は ENGINE の `GET /speakers` から作る声の一覧、**プール**は `TTS_SPEAKER_IDS` に並べた声（自動割り当てと手動選択の両方に使う）、**セッションの声**はその opt-in の間その参加者に使う声。

### 自動割り当て

`assign_auto_voice`（Discord 非依存）が、ユーザー ID の sha256 から既定の位置を決め、プールをそこから一周して、セッション内の他の参加者が使っていない最初の声を選ぶ。空きがなければ使用数が最も少ない声（同数なら巡回順で先）を選ぶ。`hash()` や `user_id % len(pool)` は使わない。snowflake の下位ビットは採番カウンタで偏り、`hash()` は再起動で変わるため。

- **ユーザーごとに固定**: プールが同じで他の参加者と衝突しなければ、セッション・再起動をまたいで同じ声になる。自動の声は DB に保存しない（ハッシュで再現できるので書き込みも移行も要らない）。
- **セッション中は変えない**: 参加時に決めた声は opt-in が終わるまで保持する。他の人が抜けて既定の声が空いても付け替えない。読み上げ中に声が変わると誰の発言か分からなくなるため。退出（VC 離脱・`/read leave`）で声も解放し、再 join で改めて割り当てる。
- 毎回声が変わる方式（参加順に先頭から、ランダム）は採らない。「この声はこの人」と覚えられず、名前を読まない代わりに声で区別する目的を果たせないため。
- **`TTS_SPEAKER_IDS` の内容や順序を変えると、全員の自動の声と選べる声が変わる**。追加したキャラクターの規約とクレジットも確認する。別の VVM の声を加えるとメモリ使用量が増える（[メモリ](#メモリ)）。
- カタログがある場合、プールのうちカタログにない ID は自動の候補から除く。除いた結果が空なら除く前のプールを使う。

### 手動選択との優先順位

`/read join` でセッションの声を決めるとき:

1. 保存済みの声があり、カタログにあり（カタログがなければ検証しない）、他の参加者が使っていなければ、それを使う。
2. 他の参加者が使用中なら**先に参加していた人を優先**する。後から来た人には、そのセッションだけ自動の手順で空いている声を割り当て、応答で知らせる。空きがなければ保存済みの声を重複して使う（使用数の少ない自動の声より本人の選択を優先）。
3. 保存済みの声がない、カタログにない、または DB の読み取りに失敗した場合は自動で割り当てる。応答で理由を知らせる。保存済みの行はカタログにない場合も**消さない**（ENGINE の一時的な差し替えで設定を失わないため）。

既に opt-in 済みの人が `/read join` をやり直してもセッションの声は変えない。

`/read voice set` は常に保存する。使用中の声を選んでも拒まず（保存は今後の参加にも効く設定で、一時的な状態で可否を決めない）、opt-in 中なら他の参加者が使っていないときだけ即座にセッションの声を差し替える。使用中なら差し替えず、次に参加したときに反映する旨を返す。`/read voice reset` は行を削除し、opt-in 中なら自分を除いた使用状況で自動の声に割り当て直す。

声は**キューに入れる時点**で投稿者のセッションの声に決める。声を変える前にキューに入った投稿は前の声で読まれる（合成時に引き直すと、待機中の投稿の声が後から変わるため）。

### カタログ

`VoicevoxClient.fetch_voices()` が `GET /speakers`（接続 3 秒・読み取り 10 秒）から、`type` が `talk`・`streaming_talk` または `type` なしの style を `Voice` にする。`sing` 系は `/audio_query` で使えないので除く。ID 重複は最初を残し、順序は ENGINE の順。応答の形が壊れていたり候補が 0 件なら `ExternalAPIError` にし、壊れた要素だけ飛ばす処理はしない。

- cog がメモリに持つ（永続化しない）。最初の利用（autocomplete・`join`・`voice set`・`voice show`）で取得する。起動時に取得しないのは、そのためだけに ENGINE を起動しないため（[オンデマンド起動](#オンデマンド起動)）。有効期間は 1 時間で、専用の `asyncio.Lock` で single-flight にする。失敗したら古いキャッシュを使い続け、60 秒は再取得しない。初回の取得後、プールにあってカタログにない ID を warning、全 ID がなければ error でログに出す。
- **`self.lock` を保持したまま `/speakers` を待たない**。`join`・`set` は更新を `self.lock` の前に済ませ、ロックの中ではメモリのカタログを参照するだけにする。2 つのロックを入れ子に取ることもしない。
- autocomplete はキャッシュだけで答え（3 秒の期限と打鍵ごとの呼び出しのため）、古ければバックグラウンド更新を起動する。NFKC と casefold で正規化した入力がラベルか ID に部分一致する声を、カタログの順に最大 25 件返す。候補は `TTS_SPEAKER_IDS` にある声だけを対象にし、そのうち通常の読み上げに使う style 名（`ノーマル`・`ふつう`・`Normal` など）に限る。感情・演技スタイルまで並べると候補が多すぎて選びにくく、ENGINE が読み込むモデルも増えるため。`choices` は 127 スタイル（ENGINE 0.26.0）が上限 25 件に収まらないので使わない。
- `set` は、カタログが古ければ更新してから判定し、数字列の ID がカタログにない場合は 1 回だけ強制更新する。カタログを取得できなければ「声の一覧を取得できませんでした。」と返して保存しない。
- カタログがない間は、`join` は保存済みの声がプール内ならそのまま使い、プール外なら自動に切り替える。`show`・`reset` はラベルの代わりに「ID n」を表示する。合成が失敗すれば既存どおりその投稿を飛ばす。

### 競合

セッションの声は opt-in と同じ 1 つの対応表（ユーザー ID → style ID）で持ち、`self.lock` の内側で読み書きする。`join` の DB 読み取りと割り当て、`set`・`reset` の DB 書き込みとセッション反映は、それぞれロックの中で 1 つの操作として行う（DB は `asyncio.to_thread`）。DB への確定順とセッションへの反映順が常に一致するので、並行する `set`・`reset`・`join` が完了した時点で、opt-in 中の人のセッションの声は DB の最終値と食い違わない（使用中で反映できなかった場合を除く）。ロックの中で待つのは SQLite の 1 回の呼び出しだけで、HTTP は待たない。

`members` も同様にロックを取らず、ハンドラの先頭から応答の直前まで await を挟まずに `session.voices` のスナップショットで文面を組み立てる（`join` の接続を待たせず、組み立ての途中で対応表が変わらない）。`join` で声を決めている途中の人は、`voices` への代入が済むまで載らない。

`show` は読み取りだけなのでロックを取らず（接続中の `join` に最大 15 秒待たされないため）、保存済みの声と現在の声がそれぞれ確定済みの値であることまでを保証する。DB の書き込みに失敗したら反映に進まず、「声の設定を保存できませんでした。」（reset は「声の設定を戻せませんでした。」）と返す。`join` での読み取り失敗は自動の声で成功させる。

## 競合と接続の管理

接続ごとにセッション（VC の ID、opt-in 者、キュー、worker、退出猶予）を作り、切断時に丸ごと捨てる。`join`・`leave`・自動退出・外部切断の処理は 1 本の `asyncio.Lock` で直列化する。これにより次を保証する。

- 別々の VC から同時に `/read join` されても接続は 1 回。ロック内でセッションを再確認する。
- 合成中（最大 30 秒）に切断・再 `/read join` されても、古い項目は新しい接続で再生されない。worker は合成後と再生直前に、自分のセッションが現役か、`/read stop` を挟んでいないかを確認する。
- bot が管理者に別 VC へ移動された場合は、ライブラリが接続を維持して `voice_client.channel` だけが変わる。これを検知して状態を破棄し、切断する。外部から切断された場合も状態を破棄し、自動再接続はしない。
- cog unload 時は worker・退出猶予を cancel し、接続していれば切断する。

opt-in が 0 人になると 5 秒の猶予後に切断する。一時的な接続断で退出と再接続を繰り返さないための猶予で、opt-in は復元しない。猶予中の `/read join` は退出をキャンセルする。猶予終了時は、セッションが同じで対象者が 0 人のときだけ切断する。

## 音声合成と再生

VOICEVOX ENGINE の `POST /audio_query` の結果を `POST /synthesis` に渡して WAV を得る（接続 5 秒・読み取り 30 秒のタイムアウト）。空・`RIFF` で始まらない応答は `ExternalAPIError`。`audio_query` の結果は `speedScale` だけを `TTS_SPEED_SCALE`（既定 1.5）で上書きして渡し、音量・ピッチ・抑揚は ENGINE の値のままにする。チャットの流れに読み上げが追いつかずキューが詰まるのを減らすための既定で、プロセス全体で 1 つの値をクライアントが保持するため、キュー済みの投稿を含め全員に同じ速度がかかる。範囲は VOICEVOX エディタの話速と同じ 0.5〜2.0 で、ENGINE が範囲外の値をどう扱うかに依存しないよう bot 側で起動時に拒否する（`nan`・`inf` も拒否）。上限は 2.0 とする。変更は再起動で反映する。

失敗時は warning ログを出してその投稿を飛ばし、キューは止めず再試行もしない。

### メモリ

ENGINE は声のモデルを VVM ファイル単位で読み込み、プロセスが終わるまで解放しない。1 つの VVM に複数のキャラクター・スタイルが入っている。加えて、推論用の領域は VVM ごとに「それまでに合成した最も長い文」に合わせて確保され、短い文に戻っても縮まない。長い投稿が 1 件来ればその VVM は最大まで膨らむので、最悪値は投稿の頻度ではなく `TTS_MAX_CHARS` で決まる。最悪のメモリ使用量はおおよそ「プールの VVM 数 × 上限の長さで膨らむ量」になる。

ENGINE 0.26.0（cpu）での実測（かなの文。RSS）:

| それまでの最長の文 | 1 VVM あたり |
|---|---|
| 30 文字 | 約 0.33 GB |
| 60 文字 | 約 0.6 GB |
| 120 文字 | 約 1.1 GB |
| 200 文字 | 約 2.2 GB |

これに基づき、既定は次のようにしている。

- プールは 2 つの VVM（`0.vvm`: ずんだもん・四国めたん・春日部つむぎ・雨晴はう、`15.vvm`: 青山龍星・小夜/SAYO）に収める。同じ VVM の声は追加してもモデルは増えないので、声の数ではなく VVM の数で絞る。旧既定（5 声、4 VVM、上限 200 文字）は最悪で約 8.3 GB だった。
- `TTS_MAX_CHARS` は 100。general VC のテキストチャットの過去の投稿（正規化後 5,125 件）では、中央値 10 文字、p99 62 文字で、100 文字を超えるのは 0.18% だった。60 にすると切り詰めが 1.09% に増える割に、減るメモリは 2 VVM で 1 GB 弱にとどまる。モーラ数は文字数の約 1.06 倍で、文字数で上限を決めて差し支えない。
- 投稿を区切って合成し上限を外す方式は採らない。99% の投稿が上限に届かず、手間に見合わない。
- 使っていない間も抱え続ける分は、[オンデマンド起動](#オンデマンド起動)でコンテナごと止めて手放せる。
- VOICEVOX CORE を直接使えば VVM を解放できるが、VVM を 2 つに固定する限り解放する対象がなく、bot のプロセスにネイティブライブラリを入れる手間だけが残るため採らない。3 つ以上の VVM を使いたくなったら再検討する。

WAV はディスクに書かず、`io.BytesIO` を `FFmpegPCMAudio(pipe=True)` へ渡す。本文を含む一時ファイルを残さないため。再生完了は `after` コールバックから Future に伝えて待つ。コールバックの二重呼び出しとループ終了後の呼び出しは無害にしてある。`play()` の `ClientException`（自動再接続中を含む）はその項目を飛ばし、`OpusNotLoaded` はセッションを切断する。

キューは 20 件まで（合成中・再生中の 1 件は含めない）。満杯のときは古いものを捨てず、新しい投稿を warning ログに残して捨てる。ログに本文は出さず、メッセージ ID と文字数だけを残す（声の ID も出さない）。

## 運用

- **Message Content Intent が必須**。TTS 有効時だけ `create_bot` が同 intent を有効にする。Developer Portal で有効化していないと discord.py が起動を拒否する（fail-fast）。無効時は従来どおり intent を付けない。`CTFBot` を直接生成して intent が無効な場合は、cog 初期化時に error ログを出す。
- intent を有効にすると、bot は guild の全メッセージ本文を受け取り、discord.py のメッセージキャッシュ（既定 1000 件）が本文をメモリに保持する。TTS が読むのは VC テキストチャットの opt-in 者だけで、ログには本文を出さず、VOICEVOX 以外の外部 API へは送らない。VOICEVOX へ送るのは読み上げる正規化済みの文だけ。
- bot には VC の Connect・Speak と、VC テキストチャットの View Channel が必要（[権限](utility.md#必要な-bot-権限)）。Read Message History は受信に必須ではない。
- ホストに **ffmpeg** と **libopus** が必要。起動時に確認し、欠けていれば error ログを出す。起動は止めず、`/read join` が「音声再生の準備ができていません。」と案内する。依存は `discord.py[voice]`（PyNaCl と davey を含む）。DAVE を要求する VC では davey が必須。
- VOICEVOX は本文をクエリ文字列で受け取る。ENGINE やリバースプロキシのアクセスログに本文が残り得るため、信頼できる同一ホストで動かし、アクセスログの扱いに注意する。外部公開しない。

`.env` には `TTS_VOICEVOX_URL=http://127.0.0.1:50021` を設定する。自動割り当てと選択候補に使う声は `TTS_SPEAKER_IDS`（カンマ区切りの style ID。既定 `3,13,2,46,8,10` の 6 件）で選ぶ。ID は ENGINE の `GET /speakers` で確認する。順序は巡回の順でもあり、空きを探すときに似た声が続かないように並べている。プールに加える声は、なるべく既存の VVM に入っているものから選ぶ（[メモリ](#メモリ)）。話速は `TTS_SPEED_SCALE`（0.5〜2.0、既定 1.5）で変える。

### オンデマンド起動

ENGINE は一度読み込んだモデルと推論用メモリを解放しないため、常駐させると使っていない間も 1〜2 GB を抱える。TTS 有効時は、bot が `TTS_VOICEVOX_CONTAINER`（既定 `voicevox`）の podman コンテナを必要なときだけ `podman start`、使い終えたら `podman stop` する（計測では `start` から `/version` 応答まで約 0.7 秒、最初の合成まで約 1.3 秒、`stop` は約 0.5 秒で、起動の待ちはほぼ問題にならない）。実装: [engine.py](../../src/ctfbot/features/tts/engine.py)（Discord 非依存）。

常駐 ENGINE にそのまま接続する設定は設けない。コンテナ以外で ENGINE を運用する環境がなく、分岐とテストが増えるだけのため。

事前にイメージの取得とコンテナの作成をしておく。bot は `start`/`stop` だけを行い、作成・削除・イメージ操作はしない。

```bash
podman pull docker.io/voicevox/voicevox_engine:cpu-latest
podman create --name voicevox --restart no -p 127.0.0.1:50021:50021 docker.io/voicevox/voicevox_engine:cpu-latest
```

`--restart no` にするのは、ホストの再起動で、使われていない ENGINE が勝手に起動しないようにするため。

前提:

- bot の実行ユーザーで rootless podman が動くこと（`/etc/subuid`・`/etc/subgid` の設定）。コンテナもそのユーザーで作成する。
- bot をサービスとして常駐させる場合は `loginctl enable-linger <user>` を有効にする。ログアウトでユーザーのプロセスと実行時ディレクトリが片付けられ、コンテナが消えるのを防ぐため。
- bot プロセスの PATH に `podman` が含まれること。

動作:

- **起動**: ENGINE への HTTP 呼び出し（カタログ取得・合成）の前に、起動済みと分かっていなければ `podman start` し、`GET /version` が通るまで 0.2 秒間隔で待つ（上限 30 秒）。起動・待機の失敗は ENGINE の失敗と同じ扱いで、合成はその投稿を飛ばし、カタログは既存の失敗処理に乗る。HTTP 呼び出しが失敗したら「起動済み」の認識を捨てるので、外部からコンテナが止められても次の利用で起動し直す（起動済みのコンテナへの `podman start` は無害）。
- **停止**: TTS セッション（VC 接続）がなく、ENGINE 呼び出しが実行中でなく、最後の利用から 300 秒（定数。設定にはしない）経ったら `podman stop` する。セッション中は発話の合間で止めず、セッションが終わった時点から 300 秒を数える。停止直前に条件を確認し直し、起動と停止は 1 本のロックで直列化する。停止中・停止直後の呼び出しは、停止の完了を待って起動し直す。
- **bot の起動・終了**: `cog_load` で、前回のプロセスが残した動作中のコンテナも使われなければ 300 秒後に止まるようにする。このとき起動のためだけにカタログを取得しない。`cog_unload` ではセッション破棄後に止める。
- podman の失敗（バイナリなし、コンテナなし、非 0 終了、30 秒のタイムアウト）は stderr の末尾を含めて warning ログに出す。bot は落とさない。本文や声の ID はログに出さない。

rootless podman を選んだ理由: コンテナは bot の実行ユーザーの権限内でしか動かず、bot が乗っ取られても攻撃者の権限は「そのユーザーでコード実行できる」状態から増えない。docker は操作に docker グループへの所属が要り、それが root 相当の権限になるため採らない。

採らなかった方法:

- systemd のソケット起動（`systemd-socket-proxyd` の idle 終了）: bot の変更は要らないが、ホスト固有の設定がリポジトリの外に出る。また見えるのは TCP の無通信だけで、セッション中かどうかを判断できず、発話の合間に止まる。
- podman の API（ソケット）の直接呼び出し: 依存が増える。`start`/`stop` だけなら CLI で足りる。

## クレジット

[VOICEVOX の利用規約](https://voicevox.hiroshiba.jp/term/)に従い、「VOICEVOX:キャラクター名」と表記する。キャラクターごとに追加の条件があり得るので、各キャラクターのページも確認する。既定のプールのクレジット:

| ID | 声 | クレジット |
|---|---|---|
| 3 | ずんだもん（ノーマル） | VOICEVOX:ずんだもん |
| 13 | 青山龍星（ノーマル） | VOICEVOX:青山龍星 |
| 2 | 四国めたん（ノーマル） | VOICEVOX:四国めたん |
| 46 | 小夜/SAYO（ノーマル） | VOICEVOX:小夜/SAYO |
| 8 | 春日部つむぎ（ノーマル） | VOICEVOX:春日部つむぎ |
| 10 | 雨晴はう（ノーマル） | VOICEVOX:雨晴はう |

- bot は使う声のクレジットを `/read join`・`/read voice show`・`/read voice set` の応答に表示し、`/read` の help にも「クレジットは `/read voice show` で確認できる」と書く。Discord VC での読み上げが規約上の「利用」にあたるかはキャラクターごとに解釈が分かれ得るため、安全側に倒している。`/read members` には、全員分を並べると文字数を圧迫するため載せない。
- `/read voice set` で選べるのは `TTS_SPEAKER_IDS` に並べた声だけ。autocomplete も ID・ラベルの直接入力もプール外は受け付けない。別の VVM の声を候補に加えるとメモリ使用量が増える（[メモリ](#メモリ)）。
- `TTS_SPEAKER_IDS` を変えるときは、追加したキャラクターの規約とクレジットを確認する。bot はクレジットを「VOICEVOX:キャラクター名」で自動生成するので、規約が別の表記を求めるキャラクターは入れない。既定のプールでは、`15.vvm` のもち子さん（20）が「VOICEVOX:もち子(cv 明日葉よもぎ)」を求めるため外している。

## 対象外

複数 guild・複数 VC の同時運用、音声の聞き取り、辞書、音量・ピッチの調整、ユーザー別・実行中の速度変更、キューの永続化、BGM、常駐参加。
